# MetadataOrder — порядок объектов метаданных

**Важность:** MINOR · **Тип:** CODE_SMELL · **Теги:** STANDARD, DESIGN · **Уровень:** конфигурация

## Что проверяет

Порядок дочерних объектов конфигурации в файле конфигурации:

- Designer: элементы `<ChildObjects>` в `Configuration.xml`;
- EDT: повторяющиеся элементы вида `<commonModules>CommonModule.Имя</commonModules>` в
  `Configuration.mdo`.

Внутри каждой группы объектов одного типа имена должны идти по возрастанию. Порядок читается
из исходного файла, а не из модели mdclasses: именно он определяет вид дерева метаданных.

## Что попадает в отчёт

По умолчанию — одно замечание на тип метаданных, а не на каждый объект:

```
src\Configuration\Configuration.mdo:3826: MINOR [MetadataOrder] Общие модули не отсортированы по имени: нарушений 22
```

Номер строки указывает на первое нарушение этого типа, `mdoRef` равен типу (`CommonModule`),
поэтому тип целиком исключается правилом `"mdo": "CommonModule"`. Полный список объектов
возвращает параметр `detail: object` — тогда сообщение выглядит как раньше:
`Объект "МодульА" должен располагаться раньше "МодульБ"`.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `mode` | string | `none` | Режим учёта префиксов: `none`, `stripPrefix`, `groupByPrefix` |
| `prefixes` | string[] | `[]` | Список префиксов; пустой список включает автоопределение |
| `detail` | string | `type` | `type` — одно замечание на тип метаданных, `object` — на каждый объект |

### Режимы префиксов

- `none` — сравнение по полному имени;
- `stripPrefix` — префикс отбрасывается, имя сравнивается так, как будто префикса нет:
  `об_Модуль` встаёт рядом с `Модуль`;
- `groupByPrefix` — объекты с одинаковым префиксом идут одним блоком, внутри блока сравнение
  по остатку имени.

Если `prefixes` пуст, префикс распознаётся по шаблону «2–5 букв и разделитель» (`об_`, `мс-`).

## Пример настройки

```json
{
  "checks": {
    "parameters": {
      "MetadataOrder": {
        "mode": "groupByPrefix",
        "prefixes": ["об_", "мс_"]
      }
    }
  }
}
```

## Плохо

```xml
<ChildObjects>
  <CommonModule>МодульБ</CommonModule>
  <CommonModule>МодульА</CommonModule>
</ChildObjects>
```

## Хорошо

```xml
<ChildObjects>
  <CommonModule>МодульА</CommonModule>
  <CommonModule>МодульБ</CommonModule>
</ChildObjects>
```

Числовые части сравниваются как числа: `Модуль2` стоит раньше `Модуль10`.

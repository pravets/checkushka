# ReportVariantNamedMain — вариант отчёта с именем Основной

**Важность:** MINOR · **Тип:** CODE_SMELL · **Теги:** STANDARD, DESIGN · **Уровень:** объект метаданных

## Что проверяет

Отчёт, у которого вариант отчёта в макете схемы компоновки данных назван шаблонно — по
умолчанию `Основной`. Имя варианта видит пользователь в списке вариантов отчёта: `Основной`
не несёт смысла, повторяется у разных отчётов и ничего не говорит о содержимом.

Сравнение имён идёт без учёта регистра, поэтому `Основной`, `основной` и ` ОСНОВНОЙ ` —
одно и то же нарушение.

Проверка читает варианты из модели mdclasses (`DataCompositionSchema.settingsVariants`),
поэтому одинаково работает для проекта EDT и выгрузки конфигуратора:

- EDT: `Reports/<Отчёт>/Templates/<Макет>/Template.dcs`;
- Конфигуратор: `Reports/<Отчёт>/Templates/<Макет>/Ext/Template.xml`.

Варианты вложенных схем (`<nestedSchema>`) не проверяются: это варианты вложенного отчёта,
а не варианты отчёта-владельца макета.

## Что попадает в отчёт

Одно замечание на каждый вариант с запрещённым именем:

```
Reports\УниверсальныйОтчет\Templates\ОсновнаяСхемаКомпоновкиДанных\Ext\Template.xml:146: MINOR [ReportVariantNamedMain] Вариант отчёта "Основной" в макете "ОсновнаяСхемаКомпоновкиДанных" назван шаблонно: имя варианта должно отражать его назначение
```

Номер строки указывает на элемент `<dcsset:name>` варианта. `mdoRef` равен
`Report.<Имя>` — это позволяет исключать проверку по отчёту целиком.

Если файл макета прочитать не удалось (или схема лежит не в файловой системе), замечание
выводится без номера строки: решение о нарушении принимает модель, а не разбор XML.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `names` | string[] | `["Основной"]` | Имена вариантов, которые считаются шаблонными |

Имена сравниваются без учёта регистра; пустые значения в списке игнорируются.

## Пример настройки

```json
{
  "checks": {
    "parameters": {
      "ReportVariantNamedMain": {
        "names": ["Основной", "Отчёт", "Вариант1"]
      }
    }
  }
}
```

## Исключение

Если отчёт поставляет вендор и переименовать вариант нельзя:

```json
{
  "ignore": [
    {
      "check": "ReportVariantNamedMain",
      "mdo": "Report.УниверсальныйОтчет",
      "reason": "отчёт поставщика"
    }
  ]
}
```

## Как исправить

Переименуйте вариант отчёта по назначению: например, `ПродажиПоМесяцам` вместо `Основной`.
Имя варианта задаётся в конфигураторе в свойствах варианта отчёта, либо в XML:
`<dcsset:name>` внутри `<settingsVariant>`.

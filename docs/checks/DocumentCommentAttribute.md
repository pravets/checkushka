# DocumentCommentAttribute — реквизит «Комментарий» у документа

**Важность:** MINOR · **Тип:** CODE_SMELL · **Теги:** DESIGN · **Уровень:** документ

## Что проверяет

У каждого документа конфигурации должен быть реквизит-комментарий: один из `names`
(по умолчанию `Комментарий` или `Comment`), тип — строка неограниченной длины
с включённым многострочным режимом. Реквизит `Комментарий` у документа — стандартное
место для пояснений пользователя, и без него документ некуда дополнить.

Проверка читает модель mdclasses (`Document.getAttributes()`, тип реквизита и
`ObjectAttribute.isMultiLine()`), поэтому одинаково работает для выгрузки конфигуратора
и проекта EDT:

- конфигуратор: `Documents/<Документ>.xml`;
- EDT: `src/Documents/<Документ>/<Документ>.mdo`.

Имена сравниваются без учёта регистра: идентификаторы 1С регистронезависимы. Из списка
`names` достаточно одного корректного реквизита; если найдены только некорректные
кандидаты, замечание выводится по первому в порядке модели. На документ — одно
замечание.

Проверяются только собственные реквизиты документа. Реквизиты табличных частей,
справочников и других объектов метаданных в область проверки не входят.

## Что попадает в отчёт

Нет реквизита:

```
Documents\Счёт.xml: MINOR [DocumentCommentAttribute] У документа "Счёт" нет реквизита "Комментарий"
```

Реквизит есть, но не строка неограниченной длины или без многострочного режима:

```
Documents\Акт.xml: MINOR [DocumentCommentAttribute] Реквизит "Комментарий" документа "Акт" должен быть строкой неограниченной длины с включённым многострочным режимом
```

Номер строки не указывается: модель mdclasses не отдаёт координаты реквизита внутри
файла документа, а подставлять строку соседнего элемента проверка не хочет. `mdoRef`
равен `Document.<Имя>` — это позволяет исключать проверку по документу целиком.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `names` | string[] | `["Комментарий", "Comment"]` | Имена реквизита-комментария; пустой список выключает проверку |
| `requireUnlimited` | boolean | `true` | Требовать строку неограниченной длины (`Length = 0`) |
| `requireMultiline` | boolean | `true` | Требовать включённый многострочный режим |

`requireUnlimited: false` разрешает строку ограниченной длины, `requireMultiline: false` —
однострочную строку. Не-строка репортится всегда: комментарий по определению строка.
Пустой `names` (или список из пустых строк) выключает проверку — опечатка в конфигурации
не должна давать замечание на каждый документ.

## Пример настройки

```json
{
  "checks": {
    "parameters": {
      "DocumentCommentAttribute": {
        "names": ["Комментарий", "Comment", "Примечание"],
        "requireUnlimited": true,
        "requireMultiline": true
      }
    }
  }
}
```

## Исключение

Если документ поставляет вендор и менять его метаданные нельзя:

```json
{
  "ignore": [
    {
      "check": "DocumentCommentAttribute",
      "mdo": "Document.ЗаказПоставщику",
      "reason": "документ поставщика"
    }
  ]
}
```

## Как исправить

В конфигураторе добавьте документу реквизит `Комментарий` с типом «Строка»,
допустимой длиной «Неограниченная» и включённым флагом «Многострочный режим».

В проекте EDT это тот же реквизит в `<attributes>` объекта:

```xml
<attributes uuid="...">
  <name>Комментарий</name>
  <type>
    <types>String</types>
    <stringQualifiers>
      <length>0</length>
    </stringQualifiers>
  </type>
  <multiLine>true</multiLine>
</attributes>
```

В выгрузке конфигуратора — свойство `<MultiLine>true</MultiLine>` и
`<v8:StringQualifiers><v8:Length>0</v8:Length></v8:StringQualifiers>` у реквизита.

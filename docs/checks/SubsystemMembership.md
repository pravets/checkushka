# SubsystemMembership — объект вне подсистемы

**Важность:** MINOR · **Тип:** CODE_SMELL · **Теги:** DESIGN · **Уровень:** объект метаданных

## Что проверяет

Объект конфигурации верхнего уровня не входит ни в одну подсистему дерева подсистем,
включая вложенные. Такой объект не виден в командном интерфейсе: обычно это признак
незавершённой конфигурации или забытого после рефакторинга объекта.

Проверка смотрит только объекты верхнего уровня. Реквизиты, формы, команды и макеты
отдельно не проверяются: они входят в подсистему вместе с владельцем. Поэтому в отчёт
не попадают ни реквизиты справочника, ни его формы.

Заимствованные объекты расширений (`MD.getObjectBelonging() == ADOPTED`) не проверяются:
их состав определяет расширение, и требовать для них место в подсистеме базовой
конфигурации нельзя.

Подсистемы ссылаются на объекты через свой состав (`Subsystem.getContent()`), а не через
иерархию владения. Проверка обходит всё дерево подсистем один раз и запоминает ссылки
из состава — в том числе из вложенных подсистем. Если объект входит хотя бы в одну
подсистему, замечания нет.

## Что попадает в отчёт

Одно замечание на объект. Строка не указывается: правило сформулировано на уровне объекта,
а не конкретной строки файла. Файл — файл объекта, если его удалось найти, иначе файл
конфигурации: `Configuration.xml` в выгрузке конфигуратора или `Configuration.mdo` в проекте EDT.

```
Catalogs/Товары/Товары.xml: MINOR [SubsystemMembership] Объект "Catalog.Товары" не входит ни в одну подсистему
```

`mdoRef` в замечании равен `Catalog.Товары` — по нему проверку можно исключить для
конкретного объекта.

Если в конфигурации ещё нет ни одной подсистемы, в отчёт попадут все объекты верхнего
уровня, кроме типов из `excludeTypes`. Для новой конфигурации это ожидаемо.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `excludeTypes` | string[] | список «сервисных» типов, см. ниже | Типы объектов, которые вправе не входить в подсистемы |

Значение по умолчанию:

```json
[
  "Subsystem",
  "Language",
  "EventSubscription",
  "CommonPicture",
  "CommandGroup",
  "CommonAttribute",
  "DefinedType",
  "Style",
  "FunctionalOption",
  "SessionParameter",
  "SettingsStorage",
  "XDTOPackage",
  "Role",
  "ScheduledJob",
  "DocumentNumerator",
  "IntegrationService",
  "WebSocketClient"
]
```

Имена — это `MDOType.nameEn()` из mdclasses (`Subsystem`, `Role`, `WebSocketClient` и т. д.),
сравнение без учёта регистра. Неизвестное имя игнорируется: опечатка не роняет запуск,
но и ничего не исключает.

Заданный список **заменяет** набор по умолчанию, а не дополняет его. Чтобы проверить,
например, общие модули, перечислите нужные типы вместе со стандартными. Явно пустой
список `[]` отключает все исключения — тогда проверяются и подсистемы, и роли.

## Пример настройки

```json
{
  "checks": {
    "parameters": {
      "SubsystemMembership": {
        "excludeTypes": ["Subsystem", "Language", "Role", "CommonModule"]
      }
    }
  }
}
```

## Исключение

Если объект поставляет вендор и трогать его нельзя:

```json
{
  "ignore": [
    {
      "check": "SubsystemMembership",
      "mdo": "Catalog.УниверсальныйСправочник",
      "reason": "объект поставщика"
    }
  ]
}
```

## Как исправить

Включите объект в состав подсистемы. В конфигураторе — вкладка «Состав» свойств подсистемы;
в проекте EDT — элемент `<content>` в `Subsystems/<Подсистема>/<Подсистема>.mdo`; в выгрузке
конфигуратора — элемент состава в XML подсистемы. Объект можно включить сразу в несколько
подсистем: замечание исчезнет, как только появится хотя бы одна.

# RequiredRoles — обязательные роли конфигурации

**Важность:** MAJOR · **Тип:** CODE_SMELL · **Теги:** STANDARD · **Уровень:** конфигурация

## Что проверяет

В конфигурации нет роли из обязательного перечня (стандарт 1С № 488):

- `ПолныеПрава` / `FullAccess`;
- `АдминистраторСистемы` / `SystemAdministrator`;
- `ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок` / `InteractiveOpenExternalReportsAndDataProcessors`.

Поиск идёт по имени без учёта регистра: `ПолныеПрава` и `FullAccess` — одна и та же роль.
Одно замечание — на каждую отсутствующую роль: если нет двух ролей, будет два замечания.

Проверяется только сама конфигурация (`Configuration.xml` в выгрузке конфигуратора или
`Configuration.mdo` в проекте EDT). Роли, добавленные расширениями, требование не закрывают:
роль, которая есть только в расширении, считается отсутствующей. Если проект — это одно
расширение без базовой конфигурации, проверка молчит.

Требование «роли должны входить в свойство „Роли по умолчанию“» в проверку не входит.

## Что попадает в отчёт

Одно замечание на каждую отсутствующую роль. Замечание привязано к файлу конфигурации, без
номера строки:

```
src\Configuration\Configuration.mdo: MAJOR [RequiredRoles] В конфигурации отсутствует обязательная роль "АдминистраторСистемы"
```

Номер строки не выводится: у отсутствующей роли нет места в файле, а подставлять строку соседнего
объекта нельзя. `mdoRef` у замечания тоже нет — это замечание на конфигурации, а не на объекте
метаданных.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `roles` | string[] | `["ПолныеПрава", "FullAccess", "АдминистраторСистемы", "SystemAdministrator", "ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок", "InteractiveOpenExternalReportsAndDataProcessors"]` | Обязательные роли конфигурации |

Список заменяет перечень по умолчанию целиком. Элементы списка группируются в требования:
русское и английское написания стандартных ролей из перечня выше считаются одной ролью, любое
другое имя — самостоятельное требование. Пустые строки игнорируются, пустой список отключает
требования.

## Пример настройки

Требуем только полные права и администратора системы:

```json
{
  "checks": {
    "parameters": {
      "RequiredRoles": {
        "roles": ["ПолныеПрава", "FullAccess", "АдминистраторСистемы", "SystemAdministrator"]
      }
    }
  }
}
```

## Плохо

Роли `АдминистраторСистемы` нет:

```xml
<ChildObjects>
  <Role>ПолныеПрава</Role>
  <Role>ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок</Role>
</ChildObjects>
```

## Хорошо

```xml
<ChildObjects>
  <Role>ПолныеПрава</Role>
  <Role>АдминистраторСистемы</Role>
  <Role>ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок</Role>
</ChildObjects>
```

## Исключение

Исключить проверку целиком:

```json
{
  "ignore": [
    {
      "check": "RequiredRoles",
      "reason": "конфигурация-надстройка, полный доступ выдаётся платформой"
    }
  ]
}
```

Исключение по `mdo` не сработает: у замечания нет ссылки на объект метаданных. Если роль
в конфигурации действительно не нужна, её проще убрать из параметра `roles`.

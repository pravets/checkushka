# YoLetterInMetadata — буква «ё» в именах и синонимах метаданных

**Важность:** MINOR · **Тип:** CODE_SMELL · **Теги:** STANDARD · **Уровень:** объект метаданных

## Что проверяет

Имя, синоним во всех языках и — если он включён параметром `properties` — комментарий объекта
метаданных. Стандарты 1С № 598 и № 474 формулируют область правила по-разному: имя и синоним,
все языки синонима или только русский, комментарий или нет. Одна параметризуемая проверка
покрывает все варианты.

- сравнение идёт без учёта регистра, поэтому значение `letters` по умолчанию (`["ё"]`)
  покрывает и «ё», и «Ё»;
- синоним проверяется по каждому языку отдельно;
- комментарии по умолчанию не проверяются;
- проверяются не только верхнеуровневые объекты, но и вложенные: реквизиты, табличные части
  и их реквизиты, команды, макеты, формы и прочие дочерние объекты модели.

Проверяются те вложенные объекты, которые mdclasses отдал в разобранной модели: если парсер
не разобрал дочерний объект, проверка его не увидит.

Проверка читает модель mdclasses (`MD.getName()`, `MD.getSynonym(): MultiLanguageString`,
`MD.getComment()`), поэтому одинаково работает для выгрузки конфигуратора и проекта EDT.

## Что попадает в отчёт

Одно замечание на пару «объект + свойство + язык синонима»:

```
Catalogs/Ёлка.xml: MINOR [YoLetterInMetadata] Имя объекта "Ёлка" содержит букву "ё"
```

Номер строки не указывается: mdclasses не отдаёт позицию имени или синонима внутри файла,
а разбор XML ради одной координаты сюда не входит. `mdoRef` указывает на конкретного
нарушителя, включая вложенные объекты, — `Catalog.Ёлка.Attribute.СтавкаЁ`. Это позволяет
исключать правило точечно.

## Параметры

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `letters` | string[] | `["ё"]` | Запрещённые буквы; сравнение без учёта регистра |
| `properties` | string[] | `["name", "synonym"]` | Что проверять: `name`, `synonym` (все языки), `comment`; неизвестные значения игнорируются |

`letters` — литеральные подстроки, а не регулярные выражения. Пустой список `letters`
отключает проверку; пустой `properties` — тоже. Чтобы не проверять синонимы, перечислите
только нужные свойства.

## Пример настройки

```json
{
  "checks": {
    "parameters": {
      "YoLetterInMetadata": {
        "letters": ["ё"],
        "properties": ["name", "synonym", "comment"]
      }
    }
  }
}
```

## Плохо

```text
Справочник "Ёлка"
Синоним "Новогодняя ёлка"
Реквизит "СтавкаЁ"
```

## Хорошо

```text
Справочник "Елка"
Синоним "Новогодняя елка"
Реквизит "СтавкаЕ"
```

## Исключение

Если объект поставляет вендор и переименовать его нельзя:

```json
{
  "ignore": [
    {
      "check": "YoLetterInMetadata",
      "mdo": "Catalog.Ёлка.Attribute.*",
      "reason": "объект поставщика"
    }
  ]
}
```

## Связь с BSL Language Server

`YoLetterUsage` в BSL LS проверяет только IDENTIFIER-токены BSL-кода и не читает имена
и синонимы метаданных — источники истины разные, проверки не дублируются.

Смежная идея про кавычки-ёлочки в текстах свойств в эту проверку не входит: `letters` —
литеральные буквы, а не шаблоны.
